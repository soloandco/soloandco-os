# Solo & Co OS

[![test](https://github.com/soloandco/soloandco-os/actions/workflows/test.yml/badge.svg)](https://github.com/soloandco/soloandco-os/actions/workflows/test.yml)

인터뷰를 통해 사용자의 실제 업무 흐름을 파악하고, 1인 창업자·프리랜서·매니지먼트 조직에 맞는 파일 기반 Business OS를 생성하는 오픈소스 프로젝트입니다.

> Status: `v0.1.0` experimental. 실제 사용자 인터뷰와 호환성 검증 전까지 구조가 변경될 수 있습니다.

## 무엇이 다른가요?

- “어떤 폴더를 원하세요?” 대신 최근 실제 업무가 어떻게 시작하고 수금으로 끝났는지 묻습니다.
- 질문지를 나열하지 않습니다. 홈페이지·소개 자료를 먼저 읽고, 자료에 없는 것만 묻습니다.
- AI는 인터뷰와 분류를 담당하고, 결정론적 생성기가 폴더를 만듭니다.
- 같은 인터뷰 JSON은 같은 프리셋·모듈 구조를 만듭니다.
- 생성 직후 고객·상품 필수 온보딩을 완료하기 전에는 홈페이지·콘텐츠·마케팅·영업 실행을 차단합니다.
- Codex나 Claude Code로 세팅하고 씁니다. 둘 중 어느 쪽을 써도 같은 규칙과 스킬을 읽습니다.
- 계약·고객·재무 등 민감 정보가 공개 예제에 포함되지 않도록 설계합니다.

## 프리셋

| 프리셋 | 대상 | 핵심 구조 |
|---|---|---|
| `management-agency` | 여러 1인 사업자를 육성하는 조직 | 영역: 고객·멤버·지원 서비스·영업·재무·계약 |
| `solo-founder` | 자신의 상품·고객·콘텐츠를 운영하는 1인 창업자 | 영역: 고객·상품·콘텐츠·재무 |
| `freelancer` | 여러 고객 프로젝트를 수행하는 프리랜서 | 영역: 고객·서비스·영업·콘텐츠·재무 |

프리셋은 `영역/` 아래만 다릅니다. 맨 위 폴더는 모두 같습니다.

선택 모듈: `automation`, `brand`, `community`, `content`, `ir`, `lecture`, `ventures`, `website`.

`ventures`는 따로 폴더를 만들지 않습니다. 실험도 끝나는 날이 있는 일이라 `프로젝트/`에 둡니다.

## 폴더는 네 가지로만 나눕니다

티아고 포르테가 「세컨드 브레인」에서 정리한 PARA 방식을 따릅니다. 주제가 아니라 **언제까지 쓰는가**로 나누기 때문에, 파일을 받았을 때 둘 곳을 고민하는 시간이 줄어듭니다.

```text
<워크스페이스>/
├── 프로젝트/   끝나는 날이 있는 일. 폴더 하나 = 일 하나 (2026-11-가나상사-홈페이지)
├── IR/         ir 모듈을 고르면 생김. 투자 라운드마다 폴더 하나
├── 영역/       끝나지 않고 계속 맡는 일. 고객·영업·콘텐츠·재무·운영
├── 기업자료/   회사 사실의 정본. 가격·연락처·핵심지표·결정기록과 받은 자료
│   ├── 제공자료/     새 자료를 일단 넣는 곳
│   ├── 원본보고서/   외부 분석 보고서 PDF
│   └── BM/<사업>/    사업별 분석
└── 보관/       끝난 프로젝트를 통째로 옮겨 두는 곳
```

- 둘 곳을 모르겠으면 `기업자료/제공자료/`에 넣습니다. 정리는 AI가 합니다.
- 폴더마다 목차 문서(`index.md`)를 두지 않습니다. 지도는 루트 `README.md` 한 장입니다.
- 끝난 프로젝트는 지우지 않고 `보관/`으로 옮깁니다. 검색은 되고 눈앞에서는 사라집니다.

## 기록은 요약 문서가 아니라 표에 쌓습니다

가격·연락처·고객 목록처럼 같은 형태로 반복되는 기록은 처음부터 빈 표로 생성됩니다. 한 줄씩 더하면 되고, AI는 표를 그대로 읽습니다. AI가 요약 문서를 계속 고쳐 쓰는 위키 방식보다 비용이 적고, 금액·조건 같은 원래 값이 바뀌지 않습니다.

숫자는 `기업자료/핵심지표.md`에 기준일을 달아 줄을 더하므로 추이가 남습니다. 정해진 주기(기본 월간, 인터뷰에서 고른 주기)마다 「점검」이라고 하면 AI가 지표마다 직전 값과 비교해 `영역/운영/점검기록.md`에 한 줄씩 남기고, 달라진 이유는 추측하지 않고 묻습니다. 주기는 생성된 `AGENTS.md`의 「점검 주기」 한 줄에서 바꿉니다.

견적서 도구(`packages/doc-mcp`)의 설정 파일도 `.soloandco/doc-mcp.config.json`으로 함께 생성됩니다. 경로를 직접 맞출 필요가 없습니다.

## IR 모듈

`ir` 모듈을 고르면 맨 위에 `IR/` 폴더가 생깁니다. 투자 라운드마다 `IR/<라운드>/` 폴더 하나를 쓰고, 그 안을 셋으로 나눕니다.

| 폴더 | 담는 것 |
|---|---|
| `작업/` | 팩트시트·원고·구성안·숫자 확인 기록 |
| `최종/` | 투자자에게 보낼 파일 |
| `자료/` | 회사가 확인해 준 서류 |

IR 제작 도구는 `기업자료/`에서 회사 사실을 읽고 `IR/<라운드>/`에 씁니다. 숫자는 모든 워크스페이스에 생기는 `기업자료/핵심지표.md` 한 곳에서 가져오므로, 수치가 바뀌어도 그 표만 고치면 됩니다. 시장·경쟁·자금 계획은 미리 표로 만들지 않습니다. 라운드마다 회사가 정하는 값이라 IR을 만들 때 팩트시트에 적습니다.

## 브랜드 모듈

`brand` 모듈을 선택하면 두 개의 파일이 함께 생성됩니다.

| 파일 | 읽는 대상 |
|---|---|
| `기업자료/브랜드/브랜드_규격.md` | 사람. 처음 값을 채우는 안내판 |
| `.agents/skills/<이름>-brand/SKILL.md` | Codex·Claude Code. 값의 정본 (`.claude/skills/`에는 이곳을 가리키는 포인터) |

인터뷰에서 홈페이지·소개 자료의 실제 색과 서체를 뽑아 두 파일에 채웁니다. 그다음부터는 "소개서 만들어줘"라고만 해도 자기 브랜드 색으로 나옵니다. 매번 색을 다시 불러줄 필요가 없습니다.

정해진 브랜드가 아직 없으면 값을 비운 채 생성됩니다. 이때 스킬은 **스스로 적용을 중단하고** 사용자에게 색을 묻도록 쓰여 있습니다. AI가 임의로 색을 고르지 않게 하기 위한 장치입니다.

스킬 폴더 이름은 ASCII로 만들어집니다. 한글 워크스페이스 이름은 `workspace-brand`로 떨어지므로 원하는 이름으로 바꿔 쓰면 됩니다.

## 시작하는 두 가지 방법

설치하기 전에 한 가지를 먼저 정합니다. 생성기를 인자 없이 실행하면 이 질문부터 나옵니다.

```
노션 템플릿을 먼저 만들까요? 설치 없이 노션에서 바로 씁니다. [Y/n]
```

| 방법 | 누구에게 | 무엇이 생기나 |
|---|---|---|
| **노션 템플릿** (기본) | 터미널을 쓰지 않는 1인 창업자 | 표 4개와 페이지 3개. 매일 「오늘 시작」 한마디로 돌아갑니다 |
| **파일 워크스페이스** | 코드 도구를 함께 쓰는 사용자 | 프리셋 기반 폴더 구조와 온보딩 관문 |

노션으로 시작하려면 [`docs/notion/template.md`](docs/notion/template.md)를 노션에서 `가져오기 > Markdown`으로 올리고, 표를 데이터베이스로 전환한 뒤, 「클로드 지시문」 페이지를 AI 도구의 지시문에 붙입니다. 설치할 것이 없습니다.

5명 이하 팀이 클로드에게 시킨 일을 빠짐없이 기록하려면 [`docs/notion/team-template.md`](docs/notion/team-template.md)를 같은 방법으로 씁니다. 표 2개(업무 기록·고객사)와 지시문으로 되어 있습니다.

두 양식 모두 일을 끝낼 때 「소요 시간」을 적습니다. 다음 견적의 근거를 쌓기 위한 칸입니다. Claude Code나 Codex로 한 일은 [`scripts/session-time.mjs`](scripts/session-time.mjs)가 세션 기록의 시각으로 재 줍니다(`node scripts/session-time.mjs --session <세션 id>`).

두 방법 모두 온보딩을 먼저 통과해야 홈페이지·콘텐츠·마케팅·영업으로 넘어갑니다.

## 빠른 시작 (파일 워크스페이스)

Node.js 20 이상이 필요합니다. `--preset`을 주면 노션 템플릿 질문을 건너뛰고, 노션 연동 여부만 한 번 묻습니다(아래 「노션 연동」).

> 터미널이 낯설면 Claude Code 같은 AI 코딩 도구에 이 README 주소를 주고 「이대로 설치해 줘」라고 하면 됩니다. Node.js 설치부터 워크스페이스 생성까지 대신 진행합니다.

```bash
git clone https://github.com/soloandco/soloandco-os.git
cd soloandco-os
npm test

node ./bin/create-soloandco-os.mjs \
  --preset solo-founder \
  --modules automation,brand,content,website \
  --target ../my-business-os \
  --name "My Business"
```

생성된 워크스페이스는 `onboarding.md`가 `blocked`인 상태로 시작합니다. 필수는 네 가지입니다. 가장 먼저 데려올 고객, 판매 상품, 팔지 않는 고객, 실제로 결과를 낸 적 있는 일. 이 넷을 운영자와 확인해 채우고 `status: active`로 바꾼 뒤 검사합니다. 구매 계기·반론·증거 같은 나머지 항목은 비워 두고 시작해도 됩니다.

```bash
cd ../my-business-os
node .soloandco/onboarding-check.mjs
```

`OK: onboarding complete`가 나온 뒤 홈페이지·콘텐츠·마케팅·영업 업무를 시작합니다. 규칙은 생성된 `AGENTS.md` 한 곳에 있고, `CLAUDE.md`는 그 파일을 가리키는 포인터입니다. `AGENTS.md`를 읽는 다른 AI 도구도 같은 규칙을 따릅니다.

### 노션 연동

파일 워크스페이스를 만들 때 한 번 묻습니다.

```
노션과 연동할까요? 맡긴 일이 노션 표에 기록되고, 사업 자료는 이 폴더에 남습니다. [y/N]
```

| 답 | 생기는 것 | AI가 하는 일 |
|---|---|---|
| **예** | `영역/운영/노션_업무기록표.md`(노션으로 가져올 업무 기록 표), `.soloandco/session-time.mjs`(소요 시간 측정), `AGENTS.md`의 노션 기록 규칙 | 일을 시작하기 전에 노션 표에 한 줄을 만들고, 끝나면 완료·결과·소요 시간을 적습니다. 답 끝에 「노션 기록:」 한 줄 |
| **아니요** (기본) | `AGENTS.md`에 노션을 쓰지 않는다는 한 줄 | 노션이 연결돼 있어도 노션에 쓰지 않습니다 |

질문 없이 정하려면 `--notion yes` 또는 `--notion no`를 붙입니다. 인터뷰 프로필에서는 `"notion": true`로 정합니다. 답할 수 없는 환경(자동 실행)에서는 `no`입니다. 선택은 `.soloandco/config.json`의 `notion`에 남고, 노션 표 주소도 그 자리(`notion.workLogUrl`)에 적습니다.

나중에 바꾸려면 `AGENTS.md`의 「노션 연동」 절과 `config.json`의 `notion` 값을 함께 고칩니다.

생성 전에 구조만 확인할 수도 있습니다.

```bash
node ./bin/create-soloandco-os.mjs \
  --preset management-agency \
  --target ../preview \
  --dry-run
```

## 인터뷰로 생성하기 (Codex·Claude Code)

1. 이 저장소 폴더에서 Codex나 Claude Code를 엽니다.
2. 「`prompts/interview.md`를 읽고 인터뷰를 진행해 줘」라고 말합니다. 질문 형식은 [`schemas/interview-profile.schema.json`](schemas/interview-profile.schema.json)을 따릅니다.
3. 인터뷰가 끝나면 AI가 요약을 보여 주고 확인을 받습니다.
4. AI가 `interview-profile.json`을 저장하고 생성기를 실행합니다. 손으로 할 때는 아래 명령입니다.

```bash
node ./bin/create-soloandco-os.mjs \
  --profile ./examples/interview-profile.json \
  --target ../sample-business-os
```

API 키는 필요하지 않습니다. 생성된 워크스페이스는 맨 위 폴더에서 Codex나 Claude Code로 엽니다. 두 도구 모두 `AGENTS.md`를 규칙으로 읽고(Claude Code는 `CLAUDE.md` 포인터를 거침), 스킬은 `.agents/skills/`(Codex)와 그곳을 가리키는 `.claude/skills/`(Claude Code)에 생깁니다.

## 안전 원칙

- 생성기는 기존 파일이 있는 폴더를 덮어쓰지 않습니다.
- 드라이브 루트와 사용자 홈 디렉터리에는 생성하지 않습니다.
- 비밀번호·토큰·은행 인증정보·불필요한 개인정보를 인터뷰하지 않습니다.
- 실제 수치가 없으면 `0`이 아니라 `unknown`을 사용합니다.
- 고객·상품 온보딩이 끝나기 전에는 AI가 빈 값을 추정해 다음 산출물을 만들지 않습니다.
- 실제 운영 저장소를 공개판으로 직접 복제하지 않습니다.

## 프로젝트 구조

```text
bin/        CLI
src/        프리셋과 생성 로직
schemas/    인터뷰 출력 계약
prompts/    모델별 인터뷰 프롬프트
docs/       아키텍처와 운영 문서
examples/   완전히 가상화된 예제
test/       생성·검증·안전 테스트
```

## 지원과 기여 범위

- 1인이 유지보수하는 프로젝트입니다. 이슈는 읽지만 응답 기한을 보장하지 않습니다.
- 환영하는 기여: 템플릿 개선, 번역, 문서 수정, 프리셋 다듬기.
- 메인테이너가 결정하는 영역: 폴더 구조, 스키마, 검사 규칙, 생성기 안전 동작, 라이선스. 구현 전에 이슈로 먼저 제안해 주세요.
