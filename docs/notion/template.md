# Solo & Co OS

1인 창업자의 운영 공간. 표 4개와 페이지 3개다. 더 만들지 않는다.

> **옮기는 법**: 노션에서 `가져오기 → Markdown`으로 이 파일을 올린다. 표는 일반 표로 들어오므로, 표 왼쪽 위 메뉴에서 **데이터베이스로 전환**한다. 전환한 뒤 아래 「열 설정」대로 선택 열의 선택지를 넣는다.

## 표 1. 온보딩

행 하나만 쓴다. 상태가 `active`가 아니면 콘텐츠·마케팅·영업을 시작하지 않는다.

| 상태 | 주 고객 | 상품 | 구매 계기 | 첫 질문 | 망설이는 이유 | 결정 기준 | 원하는 변화 | 팔지 않는 고객 | 증거 | 잘하는 것 | 지금 하는 것 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| blocked |  |  |  |  |  |  |  |  |  |  |  |

**칸마다 답할 질문**

| 칸 | 질문 |
|---|---|
| 주 고객 | 가장 먼저 데려올 고객은 누구인가 |
| 상품 | 그 고객에게 무엇을 파는가 |
| 구매 계기 | 어떤 사건이 생겼을 때 돈을 쓰는가 |
| 첫 질문 | 처음 가장 먼저 묻는 질문은 무엇인가 |
| 망설이는 이유 | 구매 전에 가장 크게 망설이는 이유는 무엇인가 |
| 결정 기준 | 무엇을 확인하면 구매를 결정하는가 |
| 원하는 변화 | 구매 뒤 어떤 상태가 되길 원하는가 |
| 팔지 않는 고객 | 누구에게는 팔지 않는가 |
| 증거 | 이를 증명할 사례·수치·산출물. 없으면 `없음` |
| 잘하는 것 | 실제 결과를 낸 적 있는 일. 둘까지만. 관심사는 적지 않는다 |
| 지금 하는 것 | 이번 달 실제로 돈과 시간이 가는 일 |

**열 설정**: `상태`는 선택 열이고 선택지는 `blocked` / `active`. 나머지는 전부 텍스트.

값을 어디선가 추정해 채우지 않는다. 사람이 답한 것만 적는다. 11칸이 다 차면 상태를 `active`로 바꾼다.

## 표 2. 할 일

| 제목 | 영역 | 상태 | 기한 | 다음 행동 | 완료일 |
|---|---|---|---|---|---|
|  |  | 할 것 |  |  |  |

**열 설정**

| 열 | 형식 | 선택지·규칙 |
|---|---|---|
| 제목 | 제목 | 동사로 끝나게. 「제안서 보내기」 |
| 영역 | 선택 | `영업` / `실행` / `콘텐츠` / `운영` |
| 상태 | 선택 | `할 것` / `진행` / `완료` / `보류` |
| 기한 | 날짜 | 비워 두지 않는다 |
| 다음 행동 | 텍스트 | 지금 당장 할 수 있는 한 동작 |
| 완료일 | 날짜 | `완료`로 바꿀 때 채운다 |

**기본 보기**: 상태가 `완료`가 아닌 것만, 기한 오름차순.

## 표 3. 오늘 기록

하루 여러 줄이어도 된다. 한 줄이면 충분하다.

| 한 줄 | 날짜 | 종류 |
|---|---|---|
|  |  | 했다 |

**열 설정**

| 열 | 형식 | 선택지 |
|---|---|---|
| 한 줄 | 제목 | 길게 쓰지 않는다 |
| 날짜 | 날짜 | 오늘 |
| 종류 | 선택 | `했다` / `잘됐다` / `막혔다` / `숫자` / `연구했다` |

**종류의 뜻**

- `했다`: 오늘 실제로 한 일
- `잘됐다`: 결과가 났거나 방법을 찾은 것
- `막혔다`: 안 풀린 것, 물어볼 사람이 없었던 것
- `숫자`: 그날 확인한 수치 하나
- `연구했다`: 잘하는 영역에서 새로 찾아 **실제로 써 본 것**. 보기만 한 것은 적지 않는다

**남의 글을 옮기지 않는다.** 콘텐츠는 이 표에서 나온다. 이 표가 비면 그날 글도 없다.

## 표 4. 콘텐츠

발행 한 건이 한 행이다.

| 날짜 | 상태 | 소재 | 원고 | 원문 URL | 24시간 | 72시간 | 대화 발생 | 건너뛴 이유 |
|---|---|---|---|---|---|---|---|---|
|  | brief |  |  |  |  |  | unknown |  |

**열 설정**

| 열 | 형식 | 선택지·규칙 |
|---|---|---|
| 날짜 | 날짜 | 발행 예정일 |
| 상태 | 선택 | `brief` / `drafted` / `approved` / `published` / `skipped` |
| 소재 | 관계 | 「오늘 기록」 표의 어느 줄에서 나왔나 |
| 원고 | 텍스트 | 그대로 올릴 수 있는 완성본 |
| 원문 URL | URL | 게시한 뒤 사람이 적는다 |
| 24시간 | 숫자 | 하루 뒤 반응 수치 하나 |
| 72시간 | 숫자 | 사흘 뒤 같은 수치 |
| 대화 발생 | 선택 | `있음` / `없음` / `unknown` |
| 건너뛴 이유 | 텍스트 | `skipped`일 때만 |

**상태의 뜻**

- `brief`: 방향·첫 문장·구성만 있다
- `drafted`: 일부 표현만 고쳐 올릴 수 있는 본문이 있다
- `approved`: 사람이 확인했다
- `published`: 게시했고 원문 URL이 있다
- `skipped`: 건너뛰었고 이유가 있다

수치를 모르면 `unknown`이다. 0으로 적지 않는다.

## 페이지 1. 시작하기

설치할 것이 없다. 네 가지면 된다.

1. **이 템플릿을 복제한다.** 오른쪽 위 「복제」
2. **클로드에 노션을 연결한다.** 설정의 커넥터에서 노션을 추가하고 **이 워크스페이스**를 고른다. 워크스페이스가 여럿이면 잘못 고르기 쉽다. 연결 뒤 「온보딩 표 읽어 줘」로 보이는지 확인한다
3. **지시문을 붙인다.** 「클로드 지시문」 페이지의 내용을 복사해 클로드 프로젝트 지시문에 붙인다
4. **「오늘 시작」이라고 말한다.** 클로드가 온보딩 표부터 채우자고 한다. 11칸이 차면 상태를 `active`로 바꾸고, 그때부터 매일 「오늘 시작」이면 된다

**지시문 첫 줄을 지우지 않는다.** 「매 대화 시작에 온보딩 표와 매뉴얼을 읽는다」가 나머지를 작동시킨다. 이 줄이 없으면 아래 지시가 전부 읽히지 않는 산문으로 남는다.

**그다음**: 매일 「오늘 시작」 10분, 주 1회 「주간」 30분. 순서와 이유는 「매뉴얼」 페이지.

**하지 말 것**: 온보딩을 건너뛰고 글부터 쓰기. 표나 열 늘리기(두 달 써 보고 판단한다). 비밀번호·계좌·주민번호를 표에 적기.

## 페이지 2. 매뉴얼

**절차만 있다.** 채널·발행 요일·주제·말투는 이 문서가 정하지 않는다. 사용자가 온보딩 표와 아래 순서도 1~2단계에서 정한다.

### 일간 루틴 (10분)

클로드에게 「오늘 시작」이라고 말하면 이 순서로 진행한다.

1. **어제 기록 확인.** 오늘 기록 표에 어제 줄이 없으면 「어제 뭐 하셨어요? 한 줄만요」로 받아 적는다
2. **오늘 할 일 3개 이하.** 기한 지난 것부터, 그다음 오늘 것. 4개째부터는 내일로 보낸다
3. **발행일이면** 브랜딩 순서도 4단계로 간다. 아니면 3단계(기록·연구)만 한다
4. **끝에 한 줄.** 오늘 기록에 `했다` 또는 `막혔다` 한 줄

밀린 것이 있으면 새 일을 만들기 전에 먼저 말한다. 덮어 두면 쌓인다.

### 주간 루틴 (30분, 주 1회)

1. **신호 3개 갱신.** 영업·실행·콘텐츠 각각 `green` / `red`. 이유 한 줄
2. **밀린 할 일 정리.** 닫거나, 기한을 옮기거나, `보류`로. 그대로 두지 않는다
3. **다음 주 발행일 생성.** 콘텐츠 표에 다음 주 발행일 행을 `brief`로 미리 만든다
4. **한 줄 회고.** 이번 주 무엇이 대화를 만들었나. 없으면 `없음`
5. **조용한 신호 하나 확인.** `red`가 하나도 없으면, 그 신호가 재는 값이 정말 그것을 재는지 하나만 확인한다. 「일이 잘 돌아가서 조용한 것」과 「재는 것이 멈춰서 조용한 것」은 화면에서 똑같이 보인다

### 퍼스널 브랜딩 순서도

**0단계. 온보딩이 먼저다.** 온보딩 표가 `active`가 아니면 시작하지 않는다. 누구에게·무엇을·잘하는 것이 없으면 글도 없다.

**1단계. 채널 하나.** 고객이 실제로 있고 글로 답할 수 있는 곳 하나만. 둘 이상은 다음 분기에 판단한다.

**2단계. 발행 요일.** 주 2~3회, 요일을 정한다. 요일마다 성격을 붙이면 소재 고르기가 쉽다. 예: 새로 써 본 것 / 막힌 것 / 숫자. 정한 요일을 콘텐츠 표에 미리 행으로 만든다.

> **「잘된 것」을 축으로 두지 않는다.** 성과는 드물게 나고, 막힌 일과 새로 써 본 일은 매일 생긴다. 잘된 것을 요일에 걸면 그 요일마다 쓸 것이 없다.

**3단계. 매일 하는 것.** 오늘 기록 한 줄. 그리고 잘하는 영역에서 새로 찾아 **실제로 써 본 것** 하나(읽기만 한 것은 세지 않는다). 이것이 발행일의 소재다.

**4단계. 발행일에 하는 것**

1. 오늘 기록에서 소재 후보를 고른다. **기록에 없는 일은 쓰지 않는다**
2. 고객 언어로 번역한다. 네 줄을 먼저 적는다. 고객 상황 / 고객 질문 / 원하는 변화 / 기록의 근거. 하나라도 비면 원고를 만들지 않는다
3. 그대로 올릴 수 있는 완성 원고를 만든다. 방향 메모가 아니다
4. 검수 5항목
   - 첫 문장에서 고객이 자기 상황을 알아보나
   - 기록에 있는 일인가
   - 남의 발견을 썼으면 출처가 본문 안에 있나
   - 본문의 요청(CTA)이 하나인가
   - **내가 실제로 올려 온 글의 규격 안인가.** 길이와 말투 둘이다
5. **사람이 직접 게시한다.** 클로드는 게시하지 않는다
6. 원문 URL을 콘텐츠 표에 적고 상태를 `published`로

> **다섯째 항목의 기준은 자기 글에서 뽑는다.** 이미 올린 글 10편 이상의 길이(공백 제외 글자 수)와 말투(문장 끝맺음)를 재서 대역을 정하고, 새 원고가 그 밖이면 올리기 전에 줄이거나 고친다. 10편이 안 되면 이 항목은 비워 둔다. 남의 규격을 대신 쓰지 않는다.

내용 검수만 통과한 원고는 손을 대야 올라가는 상태로 남는다. 그 손대는 일이 밀리면 원고는 쌓이는데 발행은 0이 된다.

**5단계. 반응.** 24시간·72시간 뒤 수치 하나씩. 「대화가 생겼나」를 판정한다. 좋아요 수가 아니라 자기 사업 이야기를 꺼낸 사람이 있었는가다. 모르면 `unknown`.

**6단계. 주간.** 무엇이 대화를 만들었는지 한 줄. 다음 주 소재 후보를 오늘 기록에서 셋 고른다.

### 하지 않는 것

- 남의 글을 주제로 삼는 것. 형식(길이·훅)까지만 참고한다
- 기록 없이 쓰는 것
- 본문마다 링크를 넣는 것. 전부 광고로 읽힌다
- 채널을 늘리는 것. 하나가 돌아가기 전에는 안 한다
- 자기 시스템 자랑. 독자가 자기를 못 찾는다

## 페이지 3. 클로드 지시문

아래 구분선 사이를 복사해 클로드 프로젝트의 지시문에 붙인다. 노션 커넥터가 연결돼 있어야 한다.

---

당신은 1인 창업자의 운영 파트너다. 노션 워크스페이스의 표 4개(온보딩·할 일·오늘 기록·콘텐츠)와 「매뉴얼」 페이지를 정본으로 쓴다.

**매 대화 시작**

- 온보딩 표를 먼저 읽는다. 상태가 `active`가 아니면 다른 일보다 온보딩을 먼저 채운다. 질문은 한 번에 하나
- 값을 문서에서 추정하지 않는다. 사람이 답한 것만 적는다

**「오늘 시작」을 들으면**

- 매뉴얼의 일간 루틴을 순서대로 진행한다
- 어제 기록이 없으면 한 줄 받는다
- 할 일은 3개 이하로 제시한다. 기한 지난 것이 먼저다
- 발행일이면 브랜딩 순서도 4단계로 간다. 아니면 기록·연구만 한다
- 밀린 것이 있으면 새 일을 만들기 전에 먼저 말한다

**「주간」을 들으면**

- 매뉴얼의 주간 루틴을 진행한다
- `red`가 하나도 없으면 신호 하나를 골라 그 값이 무엇을 재고 있는지 확인한다. 조용한 것이 잘 돌아가는 뜻인지 재는 것이 멈춘 뜻인지는 값만 보고 알 수 없다

**콘텐츠를 만들 때**

- 오늘 기록에 없는 일은 쓰지 않는다
- 고객 상황 / 고객 질문 / 원하는 변화 / 기록의 근거 네 줄을 먼저 확정한다. 하나라도 비면 원고를 만들지 않는다
- 방향 메모가 아니라 그대로 올릴 수 있는 완성 원고를 낸다
- 검수 5항목을 통과한 것만 `drafted`로 올린다
- 다섯째 항목(내가 올려 온 글의 규격)은 발행 이력에서 길이와 말투 대역을 재서 판정한다. 이력이 10편 미만이면 이 항목은 비운다
- 본문의 요청(CTA)은 하나다

**하지 않는 것**

- 외부 게시·발송·프로필 수정·댓글. 게시는 사람이 한다
- 모르는 수치를 0으로 적는 것. 모르면 `unknown`
- 없는 값을 지어내는 것. 모르면 묻는다
- 표를 늘리거나 열을 추가하는 것

**말투**

- 짧게. 결론 먼저
- 한 번에 한 질문
- 코드나 구조 설명 대신 「무엇을 하면 되는지」로 말한다
