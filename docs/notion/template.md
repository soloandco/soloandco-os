# Solo & Co OS

1인 창업자의 운영 공간. 표 4개와 페이지 3개다. 더 만들지 않는다.

표 안의 행은 **예시**다. 전부 지어낸 것이고 기록 → 글 → 문의 → 영업 → 잘됐다의 고리가 한 바퀴 이어지게 짰다. 모양을 본 뒤 지우고 시작한다.

> **옮기는 법**: 노션에서 `가져오기 → Markdown`으로 이 파일을 올린다. 표는 일반 표로 들어오므로, 표 왼쪽 위 메뉴에서 **데이터베이스로 전환**한다. 전환한 뒤 아래 「열 설정」대로 선택 열의 선택지를 넣는다.

## 표 1. 온보딩

행 하나만 쓴다. 상태가 `active`가 아니면 콘텐츠·마케팅·영업을 시작하지 않는다.

| 주 고객 | 상태 | 상품 | 구매 계기 | 첫 질문 | 망설이는 이유 | 결정 기준 | 원하는 변화 | 팔지 않는 고객 | 증거 | 잘하는 것 | 지금 하는 것 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| (예시) 직원 5명 이하 B2B 회사의 대표. 홈페이지가 있지만 문의가 안 오는 곳 | blocked | 홈페이지 리뉴얼과 소개서 한 벌. 4주 고정 가격 | 영업 미팅에서 「홈페이지 보고 연락했다」는 사람이 한 명도 없다는 걸 깨달았을 때 | 얼마나 걸리나요 | 지난번에도 만들었는데 달라진 게 없었다 | 비슷한 회사의 전후 사례 하나 | 문의가 한 달에 한 건이라도 홈페이지를 통해 들어오는 것 | 개인 쇼핑몰, 이미지만 바꾸고 싶은 곳, 다음 주까지 해 달라는 곳 | 없음 | 서비스 설명을 한 장으로 줄이는 것. 문의 이메일을 견적까지 가게 만드는 것 | 기존 고객 2곳 유지보수, 새 문의 1건 견적 중 |

**칸마다 답할 질문**

| 칸 | 질문 |
|---|---|
| 주 고객 | 가장 먼저 데려올 고객은 누구인가 |
| 상품 | 그 고객에게 무엇을 파는가 |
| 구매 계기 | 어떤 사건이 생겼을 때 돈을 쓰는가 |
| 첫 질문 | 처음 가장 먼저 묻는 질문은 무엇인가 |
| 망설이는 이유 | 구매 전에 가장 크게 망설이는 이유는 무엇인가 |
| 결정 기준 | 무엇을 확인하면 구매를 결정하는가 |
| 원하는 변화 | 구매 뒤 어떤 상태가 되길 원하는가 |
| 팔지 않는 고객 | 누구에게는 팔지 않는가 |
| 증거 | 이를 증명할 사례·수치·산출물. 처음에는 `모름`. `실행` 행이 끝날 때마다 결과를 여기 한 줄로 옮긴다 |
| 잘하는 것 | 실제 결과를 낸 적 있는 일. 둘까지만. 관심사는 적지 않는다 |
| 지금 하는 것 | 이번 달 실제로 돈과 시간이 가는 일 |

**열 설정**: 「주 고객」이 제목 열이라 맨 앞에 온다. `상태`는 선택 열이고 선택지는 `blocked` / `active`. 나머지는 전부 텍스트.

**필수는 넷이다.** `주 고객` / `상품` / `팔지 않는 고객` / `잘하는 것`. 이 넷이 차면 상태를 `active`로 바꾸고 시작한다.

나머지 일곱은 **처음에 `모름`으로 둔다.** 시작하는 사람은 고객을 만나 본 적이 없어서 「구매 계기」·「망설이는 이유」·「결정 기준」을 모른다. 모르는 것을 지어내면 그 답이 문서에 박혀 홈페이지 문구와 글의 방향을 다 틀어 놓는다. 고객과 대화할 때마다 실제로 들은 말로 한 칸씩 채운다.

값을 어디선가 추정해 채우지 않는다. 사람이 답한 것만 적는다.

## 표 2. 할 일

| 제목 | 영역 | 상태 | 기한 | 다음 행동 | 어디서 왔나 | 완료일 |
|---|---|---|---|---|---|---|
| 홈페이지 리뉴얼 문의에 견적 보내기 | 영업 | 진행 | 2026-09-05 | 범위를 3줄로 정리해서 견적과 함께 보낸다 | 콘텐츠 |  |
| 소개서 초안 넘기기 | 실행 | 진행 | 2026-09-08 | 끝: PDF 8장 전달. 오늘은 3~5장을 쓴다 |  |  |
| 8월 미수금 입금 요청하기 | 운영 | 할 것 | 2026-09-04 | 입금 요청 메일 한 통 |  |  |
| 금요일 글 게시하기 | 콘텐츠 | 할 것 | 2026-09-05 | 검수 5항목 확인 후 직접 게시 |  |  |

**열 설정**

| 열 | 형식 | 선택지·규칙 |
|---|---|---|
| 제목 | 제목 | 동사로 끝나게. 「제안서 보내기」 |
| 영역 | 선택 | `영업` / `실행` / `콘텐츠` / `운영` |
| 상태 | 선택 | `할 것` / `진행` / `완료` / `보류` |
| 기한 | 날짜 | 비워 두지 않는다 |
| 다음 행동 | 텍스트 | 지금 당장 할 수 있는 한 동작 |
| 어디서 왔나 | 선택 | `콘텐츠` / `소개` / `재구매` / `검색` / `기타`. `영업` 행에만 채운다 |
| 완료일 | 날짜 | `완료`로 바꿀 때 채운다 |

**기본 보기**: 상태가 `완료`가 아닌 것만, 기한 오름차순.

영역별 규칙은 「매뉴얼」의 사업 순서도에 있다. 표 차원에서 지킬 것은 셋이다.

- `영업` 행은 다음 행동과 기한이 둘 다 차 있어야 한다. 하나라도 비면 살아 있는 행이 아니다
- `실행` 행은 다음 행동 칸에 **무엇을 넘기면 끝인지**를 먼저 적는다
- `영업` 행을 만들 때 **「어디서 왔나」를 그 자리에서 묻는다.** 나중에는 기억나지 않는다. 이 한 칸이 신뢰가 쌓이고 있는지를 재는 유일한 근거다

**「어디서 왔나」가 신뢰를 잰다** (2026-09-04). 신뢰가 쌓였다는 것은 세 모양으로 나타난다. 모르는 사람이 글을 보고 오거나(`콘텐츠`), 아는 사람이 소개해 주거나(`소개`), 겪어 본 고객이 다시 오는 것(`재구매`)이다. 셋 다 이 한 칸의 선택지라 고객 표를 따로 두지 않는다. `검색`과 `기타`는 신뢰로 세지 않는다.

## 표 3. 오늘 기록

하루 여러 줄이어도 된다. 한 줄이면 충분하다.

| 한 줄 | 날짜 | 종류 |
|---|---|---|
| 견적서 양식을 한 장으로 줄였다. 항목 12개에서 6개로 | 2026-09-01 | 했다 |
| 범위를 안 정하고 시작한 일이 세 번째 수정 요청을 받았다 | 2026-09-02 | 막혔다 |
| AI로 회의록을 요약해 다음 행동만 뽑는 방식을 써 봤다. 30분 회의가 5줄로 줄었다 | 2026-09-03 | 연구했다 |
| 글 보고 온 문의가 견적 단계로 갔다 | 2026-09-04 | 잘됐다 |

**열 설정**

| 열 | 형식 | 선택지 |
|---|---|---|
| 한 줄 | 제목 | 길게 쓰지 않는다 |
| 날짜 | 날짜 | 오늘 |
| 종류 | 선택 | `했다` / `잘됐다` / `막혔다` / `숫자` / `연구했다` |

**종류의 뜻**

- `했다`: 오늘 실제로 한 일
- `잘됐다`: 결과가 났거나 방법을 찾은 것. **계약·수주·완료도 여기 적는다.** 다음 글감이 된다
- `막혔다`: 안 풀린 것, 물어볼 사람이 없었던 것
- `숫자`: 그날 확인한 수치 하나. 매달 한 번은 들어온 돈과 못 받은 돈을 여기 두 줄로 적는다
- `연구했다`: 잘하는 영역에서 새로 찾아 **실제로 써 본 것**. 보기만 한 것은 적지 않는다

**남의 글을 옮기지 않는다.** 콘텐츠는 이 표에서 나온다. 이 표가 비면 그날 글도 없다.

## 표 4. 콘텐츠

발행 한 건이 한 행이다.

| 제목 | 날짜 | 상태 | 소재 | 원고 | 원문 URL | 24시간 | 72시간 | 대화 발생 | 문의로 이어짐 | 건너뛴 이유 |
|---|---|---|---|---|---|---|---|---|---|---|
| 견적 항목을 12개에서 6개로 줄인 이유 | 2026-09-01 | published | 9/1 했다 | 견적서를 받고 답장이 없는 건 비싸서가 아니라 무엇을 비교해야 하는지 몰라서였다. 항목을 여섯으로 줄이니 질문이 달라졌다. | https://example.com/post-1 | 40 | 95 | 있음 | 홈페이지 리뉴얼 문의에 견적 보내기 |  |
| 범위를 안 정하고 시작하면 세 번 다시 만든다 | 2026-09-03 | drafted | 9/2 막혔다 | 세 번째 수정 요청을 받고 알았다. 상대가 바뀐 게 아니라 내가 범위를 안 적었다. |  |  |  | unknown |  |  |
| 30분 회의를 5줄로 줄인 방법 | 2026-09-05 | brief | 9/3 연구했다 |  |  |  |  | unknown |  |  |

**열 설정**

| 열 | 형식 | 선택지·규칙 |
|---|---|---|
| 제목 | 제목 | 글을 알아볼 한 줄 |
| 날짜 | 날짜 | 발행 예정일 |
| 상태 | 선택 | `brief` / `drafted` / `approved` / `published` / `skipped` |
| 소재 | 관계 | 「오늘 기록」 표의 어느 줄에서 나왔나 |
| 원고 | 텍스트 | 그대로 올릴 수 있는 완성본 |
| 원문 URL | URL | 게시한 뒤 사람이 적는다 |
| 24시간 | 숫자 | 하루 뒤 반응 수치 하나 |
| 72시간 | 숫자 | 사흘 뒤 같은 수치 |
| 대화 발생 | 선택 | `있음` / `없음` / `unknown` |
| 문의로 이어짐 | 관계 | 이 글에서 시작된 할 일 표의 `영업` 행. 없으면 비운다 |
| 건너뛴 이유 | 텍스트 | `skipped`일 때만 |

**상태의 뜻**

- `brief`: 방향·첫 문장·구성만 있다
- `drafted`: 일부 표현만 고쳐 올릴 수 있는 본문이 있다
- `approved`: 사람이 확인했다
- `published`: 게시했고 원문 URL이 있다
- `skipped`: 건너뛰었고 이유가 있다

수치를 모르면 `unknown`이다. 0으로 적지 않는다.

**「문의로 이어짐」이 이 표에서 가장 중요한 칸이다.** 좋아요와 조회수는 글이 읽혔는지만 말하고, 이 칸만이 글이 일로 바뀌었는지를 말한다. 대부분의 글은 비어 있는 것이 정상이다.

## 페이지 0. 첫 페이지

템플릿을 열면 처음 보이는 페이지다. 표 4개를 「연결된 보기」로 끌어와 한 화면에 놓는다. 새 표를 만들지 않는다.

### 규칙

- **차트를 쓰지 않는다.** 노션 무료 요금제에서 차트가 막혀 있다. 건수는 보드의 묶음 숫자와 표의 행 수로 읽는다
- **연결된 보기의 데이터베이스 제목은 숨긴다.** 보기 오른쪽 위 「···」 → 「데이터베이스 제목 숨기기」. 제목이 크게 들어와 화면을 잡아먹는다. 대신 칸마다 굵은 한 줄 라벨을 둔다
- **원본 표 4개와 페이지 3개는 맨 아래 토글 안에 넣는다.** 평소에는 안 보인다

### 구성 (위에서 아래로)

1. 머리말 한 줄과 안내 상자. 온보딩 먼저, 매일 10분·주 1회 30분, **이번 분기 숫자 하나**, 시작하기·매뉴얼·지시문 링크
2. **오늘** 2열
3. **신뢰와 고리** 2열
4. **주간 신호** 전체 폭
5. **온보딩** 전체 폭
6. 토글 「원본 표와 페이지」

### 연결된 보기 6개

| 자리 | 라벨 | 원본 | 종류 | 필터 | 정렬 | 보이는 열 |
|---|---|---|---|---|---|---|
| 오늘 · 왼쪽 55% | 할 일 | 할 일 | 표 | 상태 ≠ 완료 | 기한 오름차순 | 제목, 영역, 상태, 기한, 다음 행동, 어디서 왔나 |
| 오늘 · 오른쪽 45% | 오늘 기록 | 오늘 기록 | 표 | 없음 | 날짜 내림차순 | 한 줄, 종류, 날짜 |
| 신뢰와 고리 · 왼쪽 45% | 신뢰로 온 영업 | 할 일 | 표 | 영역 = 영업 그리고 어디서 왔나 IN (콘텐츠, 소개, 재구매) | 기한 내림차순 | 제목, 어디서 왔나, 상태, 기한 |
| 신뢰와 고리 · 오른쪽 55% | 콘텐츠 | 콘텐츠 | 표 | 상태 ≠ skipped | 날짜 내림차순 | 제목, 날짜, 상태, 대화 발생, 문의로 이어짐, 원문 URL |
| 주간 신호 | 열린 할 일, 영역별 | 할 일 | 보드 | 상태 ≠ 완료 | 기한 오름차순 | 묶음은 영역. 카드에 제목, 기한, 다음 행동 |
| 온보딩 | 온보딩 | 온보딩 | 표 | 없음 | 없음 | 전부 |

「신뢰로 온 영업」 표의 **행 수**가 신뢰 지표다. 「어디서 왔나」 열이 보이므로 세 모양(`콘텐츠`·`소개`·`재구매`)이 각각 몇 건인지도 그 자리에서 읽힌다. 표 아래 「계산 → 개수」를 켜면 합계가 숫자로도 보인다.

**이번 분기 숫자 하나**는 안내 상자에 텍스트 한 줄로 둔다. 목표 표를 만들지 않는다. 정하는 절차는 매뉴얼의 「쌓이고 있는지 보는 법」에 있다.

## 페이지 1. 시작하기

설치할 것이 없다. 네 가지면 된다.

### 1. 이 템플릿을 내 노션으로 가져온다

**공개 템플릿 링크로 왔으면** 오른쪽 위 「복제」를 누른다. 여기서 끝이다.

**마크다운 파일(`template.md`)을 받았으면** 노션에서 `가져오기 → Markdown`으로 올린 뒤 넷을 손본다.

1. 표 4개를 각각 **데이터베이스로 전환**한다 (표 왼쪽 위 메뉴)
2. 선택 열에 파일에 적힌 **선택지**를 넣는다
3. 콘텐츠 표의 「소재」·「문의로 이어짐」을 **관계 열**로 바꿔 각각 오늘 기록·할 일에 연결한다. 두 표를 먼저 만든 뒤에 해야 한다
4. 첫 페이지의 연결된 보기마다 **데이터베이스 제목을 숨긴다** (보기 오른쪽 위 「···」)

### 2. AI 도구에 노션을 연결한다

AI 도구 설정의 커넥터에서 노션을 추가하고, **이 워크스페이스**를 고른다. 워크스페이스가 여럿이면 잘못 고르기 쉽다. 연결 뒤 「온보딩 표 읽어 줘」라고 해서 보이는지 확인한다.

### 3. 지시문을 붙인다

「클로드 지시문」 페이지의 내용을 복사해 프로젝트 지시문에 붙인다.

**첫 줄을 지우지 않는다.** 「매 대화 시작에 온보딩 표와 매뉴얼을 읽는다」가 나머지를 작동시킨다. 이 줄이 없으면 아래 지시가 전부 읽히지 않는 산문으로 남는다.

### 4. 「오늘 시작」이라고 말한다

온보딩 표부터 채우자고 할 것이다. **필수는 넷이다.** 주 고객 / 상품 / 팔지 않는 고객 / 잘하는 것. 나머지 일곱은 `모름`으로 두고 고객을 만날 때마다 채운다. 넷이 차면 상태를 `active`로 바꾸고, 그때부터 매일 「오늘 시작」이면 된다.

### 그다음

- 매일: 「오늘 시작」 (10분)
- 주 1회: 「주간」 (30분). **무슨 요일에 할지 지금 정한다**
- 순서와 이유는 「매뉴얼」 페이지

### 하지 말 것

- 온보딩을 건너뛰고 글부터 쓰는 것
- 모르는 칸을 지어내서 채우는 것. `모름`이 정답이다
- 며칠 빠뜨린 뒤 그 날들을 되채우는 것. 오늘 것만 적는다
- 표나 열을 늘리는 것. 두 달 써 보고 판단한다
- 비밀번호·계좌·주민번호를 표에 적는 것

## 페이지 2. 매뉴얼

**절차만 있다.** 채널·발행 요일·주제·말투는 이 문서가 정하지 않는다. 사용자가 온보딩 표와 각 순서도 1~2단계에서 정한다.

순서도는 둘이다. **사업 순서도**(일이 들어와 돈이 되고 끝나기까지)와 **퍼스널 브랜딩 순서도**(기록이 쌓여 글이 되기까지). 둘 다 같은 표 넷을 쓰고 같은 일간·주간 루틴 안에서 돈다.

그리고 이 둘을 **하나의 고리로 잇는 것**이 아래 「공개하며 키우기」다. 글이 문의가 되고, 문의가 일이 되고, 그 일이 다시 글감이 되는 순환이다. 이 고리가 닫히지 않으면 두 순서도는 각자 열심히 돌기만 하고 서로 아무것도 주지 않는다.

### 일간 루틴 (10분)

「오늘 시작」이라고 말하면 이 순서로 진행한다.

1. **어제 기록 확인.** 오늘 기록 표에 어제 줄이 없으면 「어제 뭐 하셨어요? 한 줄만요」로 받아 적는다
2. **어제·그저께 발행 건 수치 채우기.** 콘텐츠 표에서 하루 지난 글의 「24시간」, 사흘 지난 글의 「72시간」과 「대화 발생」을 채운다. 없으면 넘어간다
3. **새로 들어온 것 분류.** 어제 이후 도착한 문의·요청을 넷 중 하나로 보낸다. 사업 순서도 2단계다
4. **오늘 할 일 3개 이하.** 할 일 표에서 기한 지난 것부터, 그다음 오늘 것. 4개째부터는 내일로 보낸다
5. **발행일이면** 브랜딩 순서도 4단계로 간다. 아니면 브랜딩 3단계(기록·연구)만 한다
6. **끝에 한 줄.** 오늘 기록에 `했다` 또는 `막혔다` 한 줄

여기까지가 오늘 몫이다. **다 하면 끝난 것이고 더 하지 않는다.** 10분을 넘기면 4번에서 고른 셋 중 하나를 내일로 보낸다.

밀린 것이 있으면 새 일을 만들기 전에 먼저 말한다. 덮어 두면 쌓인다.

### 주간 루틴 (30분, 주 1회)

**요일을 정한다.** 안 정하면 안 하게 된다. 발행 요일을 정할 때 주간 요일도 같이 정하고, 할 일 표에 `운영`으로 매주 같은 요일 행을 하나 만들어 둔다.

1. **신호 4개 갱신.** 할 일 표의 영역마다 `green` / `red`. 이유 한 줄씩

   | 영역 | `red`로 보는 조건 |
   |---|---|
   | 영업 | 다음 행동이 없는 행이 하나라도 있다 |
   | 실행 | 기한이 지났거나 7일 동안 다음 행동이 그대로다 |
   | 콘텐츠 | 이번 주 발행이 계획보다 적다 |
   | 운영 | 기한이 지난 미수금이나 서류가 있다 |

2. **`red`마다 다음 행동 하나.** 원인을 적는 것이 아니라 다음에 할 한 동작을 적는다
3. **밀린 할 일 정리.** 닫거나, 기한을 옮기거나, `보류`로 보낸다. 그대로 두지 않는다
4. **다음 주 발행일 생성.** 콘텐츠 표에 다음 주 발행일 행을 `brief`로 미리 만든다
5. **한 줄 회고.** 이번 주 무엇이 대화를 만들었나. 없으면 `없음`
6. **신뢰 확인.** 이번 주 새로 생긴 `영업` 행을 「어디서 왔나」로 나눠 센다. `콘텐츠` / `소개` / `재구매` 세 건수. 0이면 0으로 적는다
7. **조용한 신호 하나 확인.** `red`가 하나도 없으면, 그 신호가 재는 값이 정말 그것을 재는지 하나만 확인한다. 「일이 잘 돌아가서 조용한 것」과 「재는 것이 멈춰서 조용한 것」은 화면에서 똑같이 보인다

### 며칠 빠뜨렸을 때

**빠진 날을 채우려 하지 않는다.** 대부분의 시스템은 복구하려다 죽는다.

| 상황 | 오늘 하는 것 |
|---|---|
| 기록이 사흘 넘게 비었다 | 어제 것만 한 줄. 나머지 날은 비운 채 둔다 |
| 할 일에 기한 지난 것이 다섯 개가 넘는다 | 오늘 셋만 고르고 나머지는 기한을 이번 주로 한 번에 민다. 그래도 손이 안 가는 것은 `보류` |
| 발행을 두 번 걸렀다 | 밀린 원고를 올리지 않는다. 다음 발행일 것부터 새로 만든다 |
| 한 주를 통째로 쉬었다 | 주간 루틴부터 한 번 돌리고 그날은 일간을 건너뛴다 |

비운 날은 비운 채로 둔다. 그게 그 주에 무슨 일이 있었는지를 말해 주는 기록이다.

### 공개하며 키우기 (BIP)

일을 감추지 않고 하는 만큼 내보내서, 그 기록이 다음 일을 데려오게 하는 방식이다. 위 두 순서도를 이어 붙이면 다섯 단계가 된다. 새 표는 만들지 않는다.

| 단계 | 무엇을 | 어디에 남나 |
|---|---|---|
| 1 | 업무 정리 | 할 일 표 (사업 순서도) |
| 2 | 그 기록으로 콘텐츠 | 오늘 기록 → 콘텐츠 표 (브랜딩 순서도) |
| 3 | 그 글로 알려지고 문의가 옴 | 콘텐츠 표 「문의로 이어짐」 |
| 4 | 그 문의가 신뢰와 매출로 | 할 일 표 `영업` 행 「어디서 왔나」 = `콘텐츠` |
| 5 | 그 결과가 다시 글감으로 | 오늘 기록 `잘됐다` |

**끊기는 자리는 늘 3번과 4번이다.** 1·2번은 혼자서도 굴러가고 성실히 하면 쌓인다. 그런데 글이 문의로 이어졌는지를 아무도 적지 않으면, 몇 달 뒤에 「글을 계속 써야 하나」를 감으로 판단하게 된다.

#### 고리를 닫는 두 칸

**「문의로 이어짐」** (콘텐츠 표). 문의가 왔을 때 그 사람이 어느 글을 보고 왔는지 물어서 그 글의 행에 연결한다. 대부분의 글은 비어 있다. 그게 정상이다.

**「어디서 왔나」** (할 일 표, `영업` 행). 행을 만드는 그 자리에서 묻는다. `콘텐츠` / `소개` / `재구매` / `검색` / `기타` 다섯이다. 나중에는 기억나지 않는다.

이 두 칸이 없으면 3·4번은 기분으로만 존재한다.

#### 무엇까지 공개하나

공개 범위를 **먼저** 정해 두지 않으면 매번 망설이다가 안 쓰게 된다.

- **쓴다**: 내가 한 일, 막힌 것, 고친 방법, 내 숫자
- **안 쓴다**: 고객 이름·회사명 (동의 없이), 계약 금액, 아직 확정 안 된 건, 남의 실수
- **애매하면**: 주체를 나로 바꿔 쓴다. 「A사가 요구를 계속 바꿨다」가 아니라 「범위를 처음에 못 박지 않아 세 번 다시 만들었다」

#### 자랑과 공개는 다르다

**기준은 하나다. 독자가 그 글에서 자기 상황을 알아보는가.**

- 「우리 시스템은 이렇게 돌아갑니다」 → 독자가 없다. 쓰지 않는다
- 「범위를 안 정하고 시작했다가 세 번 다시 만들었다」 → 같은 일을 겪는 사람이 있다. 쓴다

같은 소재라도 내 자랑으로 쓰면 안 되고 남의 문제로 쓰면 된다. 검수 5항목의 첫 항목이 이걸 본다.

#### 이게 돌고 있는지 재는 법

숫자 하나로 충분하다. **이번 달 새 `영업` 행 중 「어디서 왔나」가 `콘텐츠`인 것.**

- 0건이 몇 달 이어지면 글의 방향이나 채널을 바꿀 때다. 더 열심히 쓰는 것으로는 안 바뀐다
- 1건이라도 나오면 그 글이 무엇을 다뤘는지 보고 같은 줄기로 더 쓴다

좋아요와 조회수로는 이 판단을 못 한다. 그건 읽혔는지만 말한다.

### 쌓이고 있는지 보는 법

궁극적으로 만들려는 것은 **신뢰와 수익이 쌓이는 구조**다. 매일과 주간은 「오늘 무엇을 하나」와 「어디가 빨간불인가」를 답하지만, 「가려는 곳에 가까워지고 있나」는 답하지 않는다. 그 답은 분기에 한 번만 본다.

#### 신뢰는 「어디서 왔나」가 잰다

신뢰가 쌓였다는 것은 세 모양으로 나타난다. 셋 다 `영업` 행의 한 칸에 들어간다.

| 모양 | 값 | 무슨 뜻인가 |
|---|---|---|
| 모르는 사람이 글을 보고 온다 | `콘텐츠` | 내가 한 말이 닿았다 |
| 아는 사람이 소개해 준다 | `소개` | 겪어 본 사람이 이름을 걸었다 |
| 겪어 본 고객이 다시 온다 | `재구매` | 결과가 기대에 맞았다 |

`검색`과 `기타`는 신뢰로 세지 않는다. 우연히 닿은 것이다.

**고객 표를 따로 두지 않는다.** 셋이 한 칸의 선택지라 표를 늘리지 않고도 잡힌다. 다만 「어느 고객에게서 수익이 오나」는 이 방식으로 잡히지 않는다. 그게 필요해지는 날이 오면 그때 표를 만든다. 미리 만들면 매일 10분이 깨진다.

#### 수익은 오늘 기록의 `숫자` 두 줄이 잰다

매달 한 번 적는 「들어온 돈」과 「못 받은 돈」이다. 새 표를 만들지 않는다. 몇 달 치를 나란히 읽으면 추이가 보인다.

#### 분기에 한 번, 목표 한 줄

분기의 첫 대화에서 넷을 확인하고 목표 한 줄을 정한다. 표를 만들지 않는다. 첫 페이지 안내 상자에 한 줄로 둔다.

1. 지난 분기 신뢰 세 건수 (`콘텐츠` / `소개` / `재구매`)
2. 지난 분기 월별 들어온 돈
3. 셋 중 무엇이 늘었고 무엇이 그대로인가 한 줄
4. 이번 분기 숫자 하나. 예: 「12월까지 소개로 온 영업 3건」

**목표는 하나다.** 여러 개를 걸면 매일 10분 안에서 아무것도 안 보게 된다. 그 하나가 신뢰 세 건수 중 하나이거나 수익 한 줄이면 된다. 새로 잴 것을 만들지 않는다.

### 사업 순서도

일이 들어와 돈이 되고 끝나기까지의 순서다. 브랜딩 순서도와 같은 표(할 일·오늘 기록)를 쓴다. 새 표를 만들지 않는다.

#### 0단계. 온보딩이 먼저다

**「팔지 않는 고객」 칸이 비어 있으면 영업을 시작하지 않는다.** 가려 받을 기준이 없으면 들어오는 대로 받게 되고, 그 일이 실행 칸을 채워 정작 팔고 싶은 일을 할 시간이 없어진다.

#### 1단계. 일이 들어오는 곳 하나

문의가 실제로 도착하는 곳을 **하나만** 정한다. 메일이든 DM이든 폼이든 상관없지만 하나여야 한다. 여러 곳을 열어 두면 어디에 답을 안 했는지 알 수 없고, 그 불안 때문에 하루에 몇 번씩 다 열어 보게 된다.

#### 2단계. 들어온 것은 그 자리에서 넷 중 하나로

매일의 첫 동작이다. 새로 도착한 것을 하나씩 넷 중 하나로 보낸다.

| 어디로 | 무엇이 | 할 일 표에 |
|---|---|---|
| 일감 | 돈이 될 수 있는 대화 | `영업`으로. 다음 행동과 기한을 함께 |
| 할 일 | 이미 맡은 일 | `실행`으로. 끝나는 조건을 함께 |
| 나중에 | 지금은 아닌 것 | `보류`로. 기한은 비운다 |
| 무시 | 나와 상관없는 것 | 적지 않는다 |

**판단을 미루지 않는 것이 이 단계의 전부다.** 미루면 받은 편지함이 할 일 목록이 되고, 그때부터는 남이 보낸 순서대로 하루가 정해진다.

#### 3단계. 영업은 다음 행동으로만 산다

`영업` 행에는 **다음 행동과 기한이 반드시 있다.** 둘 중 하나라도 비면 그 행은 살아 있는 것이 아니라 남아 있는 것이다.

- 상대 답을 기다리는 중이어도 **언제 한 번 더 연락할지**를 기한으로 적는다. 「기다린다」는 다음 행동이 아니다
- 주간에 다음 행동 없는 행을 발견하면 그 자리에서 정한다. 정할 것이 없으면 닫는다
- 온보딩의 「팔지 않는 고객」에 걸리면 초반에 닫는다. 늦게 닫을수록 비싸다

#### 4단계. 실행은 끝을 먼저 적는다

`실행` 행을 만들 때 **무엇을 넘기면 끝인지**를 한 줄로 적는다. 끝이 안 적힌 일은 끝나지 않는다. 계속 「조금 더」가 붙는다.

- 7일 동안 다음 행동이 그대로면 주간에 셋 중 하나로 판정한다. 계속 / 범위 줄이기 / 상대에게 넘김
- 판정을 안 하고 두는 것이 가장 나쁘다. 그 일은 끝나지도 않고 자리도 안 비운다
- **`완료`로 바꿀 때 온보딩의 「증거」 칸을 채운다.** 방금 끝낸 일이 그 증거다. 처음에는 `모름`이던 칸이 이렇게 채워진다

#### 5단계. 돈은 한 달에 두 줄

매달 한 번, 오늘 기록에 `숫자`로 두 줄 적는다. 표를 만들지 않는다.

- 이번 달 들어온 돈
- 아직 못 받은 돈과 그 기한

**기한이 지난 미수금이 있으면 그 자리에서 `운영` 할 일을 만든다.** 받는 일은 파는 일과 다른 일이라 `영업`에 섞으면 묻힌다.

#### 6단계. 주간

위 주간 루틴 그대로다. 영역 넷에 신호를 매기고 `red`마다 다음 행동 하나를 정한다.

### 퍼스널 브랜딩 순서도

1인 창업자에게 마케팅은 곧 자기 이름으로 말하는 것이다.

#### 0단계. 온보딩이 먼저다

온보딩 표가 `active`가 아니면 시작하지 않는다. 누구에게·무엇을·잘하는 것이 없으면 글도 없다. 이 단계를 건너뛰면 아무나 부르는 글이 쌓인다.

#### 1단계. 채널 하나

채널을 **하나만** 정한다. 고객이 실제로 있는 곳, 글로 답할 수 있는 곳. 둘 이상은 다음 분기에 판단한다.

#### 2단계. 발행 요일

주 2~3회, 요일을 정한다. 요일마다 한 가지 성격을 붙이면 소재 고르기가 쉽다. 예: 새로 써 본 것 / 막힌 것 / 숫자. 정한 요일을 콘텐츠 표에 미리 행으로 만든다.

**「잘된 것」을 축으로 두지 않는다.** 성과는 드물게 나고 막힌 일과 새로 써 본 일은 매일 생긴다. 잘된 것을 요일에 걸면 그 요일마다 쓸 것이 없다.

#### 3단계. 매일 하는 것

- 오늘 기록 한 줄
- 잘하는 영역에서 새로 찾아 **실제로 써 본 것** 하나. 읽기만 한 것은 세지 않는다

이것이 발행일의 소재다. 매일치가 없으면 발행일에 쓸 것이 없다.

#### 4단계. 발행일에 하는 것

1. 오늘 기록에서 소재 후보를 고른다. **기록에 없는 일은 쓰지 않는다**
2. 고객 언어로 번역한다. 네 줄을 먼저 적는다. 고객 상황 / 고객 질문 / 원하는 변화 / 기록의 근거. 하나라도 비면 원고를 만들지 않는다
3. 그대로 올릴 수 있는 완성 원고를 만든다. 방향 메모가 아니다
4. 검수 5항목
   - 첫 문장에서 고객이 자기 상황을 알아보나
   - 기록에 있는 일인가
   - 남의 발견을 썼으면 출처가 본문 안에 있나
   - 본문의 요청(CTA)이 하나인가
   - **내가 실제로 올려 온 글의 규격 안인가.** 길이와 말투 둘이다
5. **사람이 직접 게시한다.** AI는 게시하지 않는다
6. 원문 URL을 콘텐츠 표에 적고 상태를 `published`로
7. 나중에 이 글을 보고 문의가 오면 그때 「문의로 이어짐」을 연결한다

**다섯째 항목의 기준은 자기 글에서 뽑는다.** 이미 올린 글 10편 이상의 길이(공백 제외 글자 수)와 말투(문장 끝맺음)를 재서 대역을 정하고, 새 원고가 그 밖이면 올리기 전에 줄이거나 고친다. 10편이 안 되면 이 항목은 비워 둔다. 남의 규격을 대신 쓰지 않는다.

내용 검수만 통과한 원고는 손을 대야 올라가는 상태로 남는다. 그 손대는 일이 밀리면 원고는 쌓이는데 발행은 0이 된다.

#### 5단계. 반응

- 24시간·72시간 뒤 수치 하나씩 적는다. **일간 루틴 2단계가 이걸 매일 챙긴다.** 따로 기억하지 않아도 된다
- 「대화가 생겼나」를 판정한다. 좋아요 수가 아니라, 자기 사업 이야기를 꺼낸 사람이 있었는가다
- 모르면 `unknown`. 느슨하게 세면 숫자가 뜻을 잃는다

#### 6단계. 주간

- 무엇이 대화를 만들었는지 한 줄
- 다음 주 소재 후보를 오늘 기록에서 셋 고른다

### 하지 않는 것

- 남의 글을 주제로 삼는 것. 형식(길이·훅)까지만 참고한다
- 기록 없이 쓰는 것
- 본문마다 링크를 넣는 것. 전부 광고로 읽힌다
- 채널을 늘리는 것. 하나가 돌아가기 전에는 안 한다
- 독자가 없는 글. 내 시스템·내 성과를 소재로 쓰되 **읽는 사람이 자기 상황을 알아보게** 쓴다. 그렇게 못 쓰겠으면 그 소재는 접는다

## 페이지 3. 클로드 지시문

아래 구분선 사이를 복사해 AI 도구의 프로젝트 지시문에 붙인다. 노션이 연결돼 있어야 한다.

---

당신은 1인 창업자의 운영 파트너다. 노션 워크스페이스의 표 4개(온보딩·할 일·오늘 기록·콘텐츠)와 「매뉴얼」 페이지를 정본으로 쓴다.

**매 대화 시작**

- 온보딩 표를 먼저 읽는다. 상태가 `active`가 아니면 다른 일보다 온보딩을 먼저 채운다. 질문은 한 번에 하나
- **필수는 넷이다.** 주 고객 / 상품 / 팔지 않는 고객 / 잘하는 것. 이 넷만 받으면 `active`로 바꾸고 시작한다
- 나머지 일곱은 `모름`으로 둔다. 모른다고 하면 그대로 적는다. **지어내자고 제안하지 않는다.** 고객 대화에서 실제로 들은 말이 나오면 그때 채운다
- 값을 문서에서 추정하지 않는다. 사람이 답한 것만 적는다

**「오늘 시작」을 들으면**

- 매뉴얼의 일간 루틴을 순서대로 진행한다
- 어제 기록이 없으면 한 줄 받는다
- 콘텐츠 표에서 하루 지난 글의 「24시간」, 사흘 지난 글의 「72시간」·「대화 발생」을 채울 것이 있는지 먼저 확인하고 물어본다
- 새로 들어온 문의·요청이 있는지 묻고 일감 / 할 일 / 나중에 / 무시 중 하나로 보낸다
- 할 일은 3개 이하로 제시한다. 기한 지난 것이 먼저다
- 발행일이면 브랜딩 순서도 4단계로 간다. 아니면 기록·연구만 한다
- 밀린 것이 있으면 새 일을 만들기 전에 먼저 말한다
- 여섯 단계가 끝나면 **끝났다고 말하고 멈춘다.** 더 할 것을 찾아 주지 않는다
- 기록이 사흘 넘게 비었으면 빠진 날을 채우자고 하지 않는다. 어제 것만 받는다. 기한 지난 할 일이 다섯을 넘으면 셋만 고르고 나머지는 이번 주로 한 번에 민다

**「주간」을 들으면**

- 매뉴얼의 주간 루틴을 진행한다
- 신호는 영업·실행·콘텐츠·운영 넷이다. `red` 조건은 매뉴얼 표에 있다
- 이번 주 새 `영업` 행을 「어디서 왔나」로 나눠 센다. `콘텐츠` / `소개` / `재구매` 세 건수. 0이면 0으로 말한다
- `red`마다 원인이 아니라 다음에 할 한 동작을 받아 적는다
- `red`가 하나도 없으면 신호 하나를 골라 그 값이 무엇을 재고 있는지 확인한다. 조용한 것이 잘 돌아가는 뜻인지 재는 것이 멈춘 뜻인지는 값만 보고 알 수 없다

**일과 돈을 다룰 때**

- `영업` 행에 다음 행동이나 기한이 비어 있으면 그 자리에서 묻는다. 「기다린다」는 다음 행동으로 받지 않는다
- `실행` 행을 만들 때 무엇을 넘기면 끝인지를 함께 받는다
- 7일 동안 다음 행동이 그대로인 `실행` 행은 주간에 계속 / 범위 줄이기 / 상대에게 넘김 중 하나로 판정받는다
- `실행` 행을 `완료`로 바꿀 때 온보딩의 「증거」 칸에 그 결과를 한 줄로 옮긴다
- 새 달의 첫 대화에서 이번 달 들어온 돈과 못 받은 돈을 묻고 오늘 기록에 `숫자`로 적는다. 기한 지난 미수금이 있으면 `운영` 할 일을 만든다
- 온보딩의 「팔지 않는 고객」에 걸리는 문의는 초반에 짚어 말한다
- `영업` 행을 만들 때 **「어디서 왔나」를 그 자리에서 묻는다** (`콘텐츠`/`소개`/`재구매`/`검색`/`기타`). 나중에 채우지 않는다. 전에 일했던 고객이면 `재구매`다
- 「어디서 왔나」가 `콘텐츠`면 어느 글인지 묻고 콘텐츠 표의 「문의로 이어짐」에 연결한다
- 계약·수주·완료 소식을 들으면 오늘 기록에 `잘됐다`로 적는다. 다음 글감이다

**분기의 첫 대화에서**

- 매뉴얼의 「쌓이고 있는지 보는 법」을 진행한다. 지난 분기 신뢰 세 건수와 월별 들어온 돈을 먼저 세어 말한다
- 무엇이 늘었고 무엇이 그대로인지 한 줄로 정리한다
- 이번 분기 숫자 하나를 받아 첫 페이지 안내 상자에 적는다. 목표는 하나다. 여러 개를 받지 않는다
- 새로 잴 것을 만들자고 제안하지 않는다

**콘텐츠를 만들 때**

- 오늘 기록에 없는 일은 쓰지 않는다
- 고객 상황 / 고객 질문 / 원하는 변화 / 기록의 근거 네 줄을 먼저 확정한다. 하나라도 비면 원고를 만들지 않는다
- 방향 메모가 아니라 그대로 올릴 수 있는 완성 원고를 낸다
- 검수 5항목을 통과한 것만 `drafted`로 올린다
- 고객 이름·회사명·계약 금액·미확정 건은 쓰지 않는다. 애매하면 주체를 사용자로 바꿔 쓴다
- 사용자의 시스템이나 성과가 소재여도 좋다. 다만 읽는 사람이 자기 상황을 알아보게 쓴다. 그렇게 못 쓰겠으면 그 소재는 접자고 말한다
- 다섯째 항목(내가 올려 온 글의 규격)은 발행 이력에서 길이와 말투 대역을 재서 판정한다. 이력이 10편 미만이면 이 항목은 비운다
- 본문의 요청(CTA)은 하나다

**하지 않는 것**

- 외부 게시·발송·프로필 수정·댓글. 게시는 사람이 한다
- 모르는 수치를 0으로 적는 것. 모르면 `unknown`
- 없는 값을 지어내는 것. 모르면 묻는다
- 표를 늘리거나 열을 추가하는 것

**말투**

- 짧게. 결론 먼저
- 한 번에 한 질문
- 코드나 구조 설명 대신 「무엇을 하면 되는지」로 말한다
