# Solo & Co OS · 팀 업무 기록

5명 이하 팀의 업무 기록장. 표 2개와 페이지 3개다. 1인용 [template.md](template.md)와 별개로 쓴다.

**목적은 하나다. 클로드에게 시킨 일과 말한 일이 노션에 빠짐없이 남는 것.** 할 일 관리·보고·집계는 이 기록이 쌓인 뒤에 따라온다.

표 안의 행은 **예시**다. 회사·사람 이름은 전부 지어낸 것이다. 모양을 본 뒤 지우고 시작한다.

> **옮기는 법**: 노션에서 `가져오기 → Markdown`으로 이 파일을 올린다. 표는 일반 표로 들어오므로, 표 왼쪽 위 메뉴에서 **데이터베이스로 전환**한다. 전환한 뒤 아래 「열 설정」대로 선택지·관계·사람 열을 맞춘다.

## 표 1. 업무 기록

한 행이 일 하나다. 「할 것」으로 태어나 「완료」로 끝나도 같은 행이다. 할 일 목록과 한 일 기록을 나누지 않는다.

| 제목 | 상태 | 분류 | 종류 | 담당자 | 고객사 | 기한 | 완료일 | 메모 | 근거 링크 | 기록 경로 |
|---|---|---|---|---|---|---|---|---|---|---|
| 가나상사 견적서 보내기 | 완료 | 영업 | 약속 | 김하나 | 가나상사 | 2026-09-03 | 2026-09-03 | 지시: 「가나상사에 9월 견적 보내 줘」. 결과: 견적서 1부 작성, 사람이 메일로 발송 | https://example.com/quote-1 | 클로드 |
| 다라기관 회신 받기 | 대기 | 지원사업 | 후속 확인 | 이두리 | 다라기관 | 2026-09-10 | | 담당자가 9/10까지 심사 일정을 알려 주겠다고 함 | | 직접 |
| 사업자 등록증명 발급하기 | 할 것 | 행정 | 내부 | 김하나 | | 2026-09-05 | | 지시: 「등록증명 새로 떼 둬야 해」 | | 클로드 |

**열 설정**

| 열 | 형식 | 선택지·규칙 |
|---|---|---|
| 제목 | 제목 | 동사로 끝나게. 「견적서 보내기」 |
| 상태 | 선택 | `할 것` / `진행` / `대기` / `완료` / `보류` |
| 분류 | 선택 | `행정` / `영업` / `개발` / `지원사업` / `파트너` / `운영` / `기획`. 팀에 맞게 바꿔도 되지만 일곱을 넘기지 않는다 |
| 종류 | 선택 | `내부` / `약속` / `후속 확인` |
| 담당자 | 사람 | 그 일을 하는 사람 |
| 고객사 | 관계 | 「고객사」 표. 내부 일이면 비운다 |
| 기한 | 날짜 | `대기`면 다시 확인할 날 |
| 완료일 | 날짜 | `완료`로 바꿀 때 채운다 |
| 메모 | 텍스트 | 지시 원문과 맥락. 끝날 때 결과 한 줄을 덧붙인다 |
| 근거 링크 | URL | 결과물·메일·문서 위치 |
| 기록 경로 | 선택 | `클로드` / `직접` |

열 두 개를 더 켠다. 노션이 알아서 채우므로 사람도 클로드도 손대지 않는다.

| 열 | 형식 |
|---|---|
| 작성자 | 생성자 |
| 만든 때 | 생성 일시 |

**상태의 뜻**

- `할 것`: 아직 손대지 않았다
- `진행`: 손댔고 끝나지 않았다
- `대기`: 상대 답을 기다린다. 기한에 **다시 확인할 날**을 적는다. 날짜 없는 대기는 잊힌다
- `완료`: 끝났다. 완료일과 결과 한 줄이 있다
- `보류`: 당분간 안 한다. 지우지 않는다

**종류의 뜻**

- `내부`: 우리끼리의 일
- `약속`: 우리가 고객에게 하겠다고 한 것. **고객사와 기한이 둘 다 있어야 한다**
- `후속 확인`: 고객이 나중에 알려 주겠다고 한 것. 기한은 다시 물어볼 날

약속을 따로 두는 이유는 하나다. 고객 신뢰는 약속을 지켰는지로 쌓이는데, 다른 일에 섞이면 기한을 넘겨도 아무도 모른다.

## 표 2. 고객사

고객·기관·파트너 한 곳이 한 행이다. 업무 기록을 고객사별로 모아 보기 위한 표라 칸을 늘리지 않는다.

| 이름 | 관계 | 담당자 | 메모 |
|---|---|---|---|
| 가나상사 | 고객 | 김하나 | 9월부터 월 단위 계약 |
| 다라기관 | 기관 | 이두리 | 지원사업 주관기관 |

**열 설정**

| 열 | 형식 | 선택지 |
|---|---|---|
| 이름 | 제목 | 사업자등록상 이름. 줄임말을 쓰지 않는다 |
| 관계 | 선택 | `고객` / `잠재` / `기관` / `파트너` |
| 담당자 | 사람 | 주 담당 한 명 |
| 메모 | 텍스트 | 한두 줄 |

업무 기록 표의 「고객사」 관계 열을 만들 때 **양방향**으로 켠다. 그러면 이 표에 「업무 기록」 열이 생겨 고객사마다 쌓인 일이 바로 보인다.

## 페이지 0. 첫 페이지

표 2개를 「연결된 보기」로 끌어와 한 화면에 놓는다. 새 표를 만들지 않는다.

| 라벨 | 원본 | 종류 | 필터 | 정렬 |
|---|---|---|---|---|
| 내 일 | 업무 기록 | 표 | 담당자 = 나, 상태 ≠ 완료·보류 | 기한 오름차순 |
| 지켜야 할 약속 | 업무 기록 | 표 | 종류 = 약속, 상태 ≠ 완료 | 기한 오름차순 |
| 기다리는 중 | 업무 기록 | 표 | 상태 = 대기 | 기한 오름차순 |
| 이번 주 끝낸 일 | 업무 기록 | 표 | 완료일 = 이번 주 | 완료일 내림차순 |
| 전체 흐름 | 업무 기록 | 보드 | 상태 ≠ 보류 | 묶음은 상태 |
| 고객사 | 고객사 | 표 | 없음 | 이름 |

「내 일」의 담당자 필터는 「나」로 둔다. 보는 사람마다 자기 일이 뜬다.

## 페이지 1. 시작하기

### 1. 요금제

노션 무료 요금제는 **멤버가 2명 이상**이면 블록 수에 상한이 걸린다. 게스트는 10명까지 무료이고 이 상한에 들지 않는다. 그래서 멤버 1명에 나머지를 게스트로 두면 무료로 시작할 수 있다. 다만 **게스트는 클로드 연결이 안 될 수 있다.** 노션은 게스트가 통합을 추가하지 못하게 한다. 게스트의 클로드가 표에 쓰지 못하면 이 템플릿의 목적이 무너진다.

그래서 먼저 한 명으로 시험한다.

1. 멤버가 이 페이지에 팀원 한 명을 게스트로 초대한다
2. 그 팀원이 자기 클로드에서 노션을 연결한다
3. 「업무 기록 표 읽어 줘」와 「테스트 행 하나 만들어 줘」를 시킨다

둘 다 되면 무료로 간다. 하나라도 안 되면 클로드로 기록할 사람을 멤버로 두고 **Plus 이상**에서 시작한다. 수정 이력은 무료 7일, Plus 30일이다 (노션 요금제 페이지, 2026-10 확인).

### 2. 팀원마다 자기 노션 계정으로 클로드를 연결한다

공용 계정 하나로 연결하지 않는다. 각자 연결해야 노션의 「작성자」 열에 실제로 시킨 사람이 남는다. 연결 뒤 「업무 기록 표 읽어 줘」라고 해서 보이는지 확인한다.

### 3. 지시문을 두 곳에 붙인다

- **클로드 프로젝트 지시문**: 「클로드 지시문」 페이지 전체
- **클로드 개인 설정(모든 대화에 적용)**: 아래 한 줄. 프로젝트 밖에서 시킨 일도 남게 하려는 것이다

```
업무를 시키거나 업무 이야기를 하면 노션 「업무 기록」 표에 먼저 기록하고, 답 끝에 「노션 기록:」 한 줄을 붙인다.
```

**두 곳 모두 붙인다.** 프로젝트 지시문만 있으면 프로젝트 밖 대화가 새고, 개인 설정만 있으면 세부 규칙이 빠진다.

### 4. 하루 써 보고 확인한다

첫날 끝에 「마무리」라고 말한다. 그날 남은 기록이 목록으로 나온다. 빠진 일이 있으면 그 자리에서 넣고, 왜 빠졌는지 한 줄을 이 페이지 아래에 적는다. 빠지는 모양이 보이면 지시문을 고친다.

### 하지 말 것

- 표나 열을 늘리는 것. 한 달 써 보고 판단한다
- 기록을 지우는 것. 안 할 일은 `보류`로 둔다
- 비밀번호·계좌번호·주민번호를 적는 것

## 페이지 2. 클로드 지시문

아래 구분선 사이를 복사해 클로드 프로젝트 지시문에 붙인다. 노션이 연결돼 있어야 한다.

---

당신은 이 팀의 업무 기록 담당이다. 노션의 「업무 기록」과 「고객사」 표가 정본이다. **기록이 가장 중요하다. 일을 잘하는 것보다 빠짐없이 남기는 것이 먼저다.**

**무엇을 기록하나**

- 사용자가 일을 시킨 것. 메일·문서 초안, 견적, 조사, 정리, 일정 잡기
- 사용자가 했다, 하고 있다, 할 거라고 말한 업무
- 고객이나 기관이 무엇을 하겠다고 했다는 이야기 (`후속 확인`)
- 기록하지 않는 것: 일반 지식 질문, 설명 요청, 잡담
- **애매하면 기록한다.** 지우는 비용이 빠뜨리는 비용보다 작다. 영수증에 「(애매해서 기록)」을 붙인다

**순서: 기록 먼저, 일은 나중**

1. 일을 받으면 **작업을 시작하기 전에** 업무 기록에 행을 만든다. 상태 `진행`, 기록 경로 `클로드`, 메모에 지시 원문
2. 만들기 전에 같은 고객사·비슷한 제목의 미완료 행을 찾는다. 있으면 새로 만들지 않고 그 행을 고친다
3. 일을 한다
4. 끝나면 같은 행을 고친다. 상태 `완료`, 완료일 오늘, 메모 끝에 `결과:` 한 줄, 결과물 위치가 있으면 근거 링크
5. 대화 안에서 끝나지 않으면 `진행`이나 `대기`로 두고 기한을 받는다
6. 한 메시지에 한 일과 할 일이 섞여 있으면 행을 나눈다. 「메일 보냈고 월요일에 서류 낼 예정」은 `완료` 하나와 `할 것` 하나다

기록을 먼저 하는 이유: 대화가 중간에 끊기거나 일이 실패해도 「시켰다」는 사실은 남는다.

**칸 채우는 법**

- 담당자: 말한 사람. 다른 사람에게 맡기는 일이면 그 사람
- 분류: 일곱 중 하나. 고르기 어려우면 가장 가까운 것을 고르고 영수증에 적는다
- 종류: 고객에게 하겠다고 한 일이면 `약속`. 약속에는 고객사와 기한이 반드시 있다. 없으면 그 자리에서 묻는다
- 고객사: 표에서 이름을 찾아 연결한다. 비슷한 이름이 여럿이면 묻는다. 없으면 새로 만들고 영수증에 「고객사 새로 만듦」을 붙인다
- 기한: 사용자가 말한 날짜만 적는다. 말하지 않았으면 비우고 `약속`·`대기`일 때만 묻는다
- 모르는 값은 지어내지 않는다. 비운다

**답 끝의 영수증**

기록한 답에는 마지막에 한 줄을 붙인다.

```
노션 기록: <제목> · <상태>
```

여러 건이면 한 줄에 하나씩. **기록에 실패하면 `노션 기록 실패: <이유>`로 적는다.** 조용히 넘어가지 않는다. 영수증이 없는 답은 기록할 일이 없었다는 뜻이어야 한다.

**「오늘」을 들으면**

말한 사람이 담당자인 행에서 넷을 보여 준다.

1. 기한이 지난 것
2. 오늘이 기한인 것
3. `대기` 중 다시 확인할 날이 온 것
4. 3일 안에 기한이 오는 `약속`

**「마무리」를 들으면**

이번 대화에서 만들거나 고친 행을 목록으로 보여 주고, 대화에 나왔는데 기록 안 된 일이 있는지 스스로 훑어서 말한다. 빠진 것이 있으면 넣을지 묻는다.

**「주간」을 들으면**

- 이번 주 `완료` 건수를 분류별로 센다. 0이면 0이라고 말한다
- 기한이 지난 미완료 행을 담당자별로 보여 준다
- `약속` 중 기한을 넘긴 것을 따로 말한다
- `대기` 중 기한이 없는 행이 있으면 다시 확인할 날을 받는다

**하지 않는 것**

- 메일 발송·외부 게시·서류 제출. 초안까지 만들고 보내는 것은 사람이 한다. 보낸 뒤 사용자가 알려 주면 그 행을 `완료`로 고친다
- 행 삭제. 안 할 일은 `보류`
- 표나 열을 추가하는 것
- 비밀번호·계좌번호·주민번호를 기록하는 것

**말투**

- 짧게. 결론 먼저
- 한 번에 한 질문
